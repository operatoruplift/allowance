Phone receipts remain readable at 320px, expanded print evidence is available immediately, expired authentication returns to login, and external-agent purchases count correctly. The rehearsal, useful output, denied probe and ambiguous-settlement examples remain explicitly simulated.
- **Payment and tool boundaries:** bounded schema-validated facilitator responses, strict useful-result validation, exact snapshot signature membership, grounded report citations, original-payment recovery, and network-bound receipt metadata. The operator must account for post-backup activity before an explicit offline recovery approval. No signed uncertainty is automatically released.
- **Documentation and CI:** complete configuration reference, receipt contract, integration status, deployment/recovery instructions, current demo script, and a secretless container build/restart verification job. Existing licensing, historical evidence and other projects are preserved.

## Migration and rollback

Schema version 3 adds recovery-lock metadata. It does not reinterpret historical policy networks, amounts or receipt evidence. New receipt exports add `receiptVersion: 1` and available policy/catalog/payment identity fields; legacy missing fields remain unavailable. See the [receipt compatibility contract](receipt-contract.md).

Back up through the supported SQLite backup command before deployment and validate the artifact. Start the candidate against the durable journal with signing disabled; inspect original unresolved receipts before enabling any separately authorized capability. Roll back code only to a binary compatible with the current schema, preserving the current volume and financial identities. Restoring an older journal is a locked recovery procedure, never a routine rollback. Exact commands and post-restore accounting requirements are in [runtime recovery](runtime-recovery.md).
